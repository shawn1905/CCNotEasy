# 评审：HTML demo 版 vs Vite 主线

> 对照对象：另一 agent 落地的 `demo/`（及根目录 `red-cliffs-mobile-demo.html`）  
> 参照：`docs/design/fun-from-probably-stolen.md`（《深空当铺》好玩三刀）  
> 对照主线：Vite + React（决策台 / 史料库）  
> 日期：2026-11-27（Asia/Shanghai）  
> 原则：**先逻辑与手感；文笔与双栈治理分开谈**

---

## 0. 范围说明

仓库里「另一 agent 的版本」指的是 **15 分钟手机 HTML 切片**（commit 含 `feat(demo): archive polished Red Cliffs 15-min mobile HTML demo`），不是第二份《当铺》分析 MD。

| 路径 | 角色 |
|------|------|
| `demo/` + `demo/src/*` | 可构建的源码与引擎 |
| `red-cliffs-mobile-demo.html` | 打平后的单文件演示 |
| `src/`（Vite） | 本会话主线：决策台 + gloss + dossiers |

---

## 1. 总评

**HTML demo 在「手感」上明显强于当前 Vite 主线。**  
它更接近《深空当铺》那类「信息即玩法」：先动手改信 / 戳名册，再看到账本跳动，最后才 A/B。Vite 决策台仍偏「更认真的阅读器」。

**文笔上更活，但史料纪律更松**（拟写多、玩笑密度更高），与项目「考据优先、幽默 ≤ 1/10」有张力——好玩，但容易偏成演义小品。

**一句话：** demo 该当 **玩法原型库**；Vite 该当 **考据与产品主仓**。应吸收，不应双栈长期并行。

---

## 2. 对齐《当铺》三刀

| 当铺课 | demo 落点 | 评级 |
|--------|-----------|------|
| 信息即玩法 | `wordsmith` 改《遗孙权书》三处措辞；`inspect` 点名册三条履历戳破 | **强** |
| 会咬人的时钟 | 顶栏钱帛 / 粮草 / 兵力 + 抉择即时结算条 | **中强**（有体感；缺自涨死线） |
| 灰色甜头 | `isBait`、虚报八十万、压疫报仍号满员 | **中** |
| 窗口感 | 巡营所见、医棚气味、廊下名册 | **强** |
| 再玩动机 | 已解锁结局收集、破绽计数 `clues_found` | **有雏形** |

互动件是 demo 的王牌：改信立刻有账房 / 参谋接茬；翻名册涨 `clues_found` 再改后面口径——**判断有反馈**，比「读完再选」上头得多。

按 `fun-from-probably-stolen.md` 的 6 条验收，demo 大约过 **1、2、4、6** 的一部分；**第 3 条（会自己涨的死线）未过**。

## 3. demo 机制速览（便于合并时对表）

### 3.1 状态

- 资源：`money` / `grain` / `troops`（HUD 展示）  
- 旗帜类：`haste`、`plague_honesty`、`loose_ships`、`suspect_defection` 等  
- 技巧 / 进度：`rhetoric_bluff`、`wit_sharp`、`clues_found`、`jingzhou_trust`、`hefei_aid`  

### 3.2 章节骨架

```text
序 江陵大帐
壹 会猎笔锋   ← wordsmith 拟《遗孙权书》
贰 降将名册   ← inspect 戳履历
叁 袖中疫报
肆 合肥急报
伍 铁索连舟
陆 东南风信
柒 乌林战报
```

### 3.3 关键交互型

| widget | 玩法 | 反馈 |
|--------|------|------|
| `wordsmith` | 点高亮槽切换措辞 | 即时评论 + vars（虚声 / 尖笔） |
| `inspect` | 点名册条目「刮纸背」 | 线索分析 + `clues_found` |
| 普通 A/B | 两害抉择 | `effects` 改资源；`isBait` 标诱向；结算条 |

### 3.4 体验层

- 顶栏资源条 + 浮动 delta  
- 抉择后结算文案（「预支一旬漕运」等当面理由）  
- 氛围 mood、打字推进、音效 / 触感（工程内已接）  
- 结局收集（discovered endings）

## 4. 硬伤

### 4.1 双栈分裂

Vite 主工程（决策台 + 史料库）与 `demo/` HTML 是两套叙事与状态机。长期会抢主线：评审可当「可合并原型」，不可当「第二正式产品」。

### 4.2 死线仍是静态条，不是房租

资源因选择而扣，但没有「过一天 → 江东定战 +1 / 疫扩散 +1」这种 **自动追人的时钟**。这是相对《当铺》最缺的一刀。

### 4.3 史料层偏表演

gloss 有出处，但互动反馈大量「拟写接茬」，幽默密度明显高于 1/10。冲「好玩」可以；冲「考据切片」易被打成演义小品。

### 4.4 微循环未铺满

会猎笔锋、降将名册有 widget；疾疫及以后多回落到长对话 + A/B。前半像游戏，后半又像阅读器。

### 4.5 工程可维护性

单文件约 7k 行 HTML + 手写引擎，迭代史料库 / 决策台成本高；与 React 内容管道（`dossiers` / `gloss` / `deliberations`）不通。

---

## 5. 对照表：Vite 主线 vs HTML demo

| 维度 | Vite（主线） | HTML demo（另一 agent） |
|------|--------------|-------------------------|
| 史料库 / 本议 | 厚、可检索、分题 | 薄、嵌在气泡 |
| 拍板前互动 | 走动 / 问策 / 翻卷（菜单） | 改信 / 验名册（操作） |
| 资源体感 | 文案代价为主 | HUD 数字跳动 |
| 世界感 | 有走动文案，偏说明 | 巡营气味、空间更强 |
| 诱向史实 | 选项 hint | `isBait` + 堂上目光 |
| 产品形态 | 可演进主仓 | 演示向、难接考据管线 |
| 幽默配额 |  intentionally 压低 | 明显更高 |

**结论：** demo 赢在 **玩法原型**；Vite 赢在 **史料基建**。应吸收 demo 的 widget + HUD + bait / 结算，接到 Vite，而不是两套并行养。

---

## 6. 合并优先级（性价比序）

```text
1) 移植两类 widget 到 Vite 第一难 / 第二难
   - wordsmith：拟书改词
   - inspect：名册戳破
   （先 1 难做透，验证手感）

2) 顶栏三资源 + 抉择结算条
   （死线的半成品；与 annotations-and-resources.md 对齐）

3) 加一条自涨死线
   - 主：江东定战倒计时
   - 副：疫扩散
   （demo 也没补上的当铺核心）

4) 压幽默配额
   - 接茬改成冷反馈（账房抖算筹可留，段子收）
   - 标签继续区分 史载 / 注 / 拟写

5) 归档或降级独立 HTML
   - demo/ 保留为参考实现
   - 避免继续双栈加戏
```

---

## 7. 合并时的纪律（防偏题）

1. **史实当证物，不当段子燃料** — widget 反馈优先引用 dossier / gloss，少发明俏皮接茬。  
2. **短利必须进 HUD** — 凡 A/B 改资源，当面结算条必出数字 + 理由。  
3. **脏招要可吹** — 虚报、压疫、密泊至少各留一句玩家能复述的短利句。  
4. **后半章也要微循环** — 疾疫 / 船阵 / 来降各至少一个 inspect 或等价操作，禁止只在前两章「像游戏」。  
5. **单主仓** — 新功能只进 Vite；HTML demo 只作对照，不平行加章节。

---

## 8. 验收（合并切片过关标准）

做完「第一难 = wordsmith + HUD + 决策台可选」后，自测：

1. 不读长铺垫也能开始改信 / 点槽  
2. 改词立刻有非灌输式反馈（最好挂史料或账本）  
3. A/B 后顶栏数字跳、结算条说清理由  
4. 至少一条诱向（bait）短利当场兑现  
5. 幽默整节仍可控（体感 ≤ 1/10）  
6. 玩家能用一句话说清：「我那局靠什么脏活 / 虚声撑过去」  

不验收：HTML 单文件是否继续美化；字数是否继续涨。
